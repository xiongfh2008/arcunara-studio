# RC20A — 团队账号与项目访问控制（第一阶段）

## 安全定位

RC20A 提供默认关闭的管理员创建成员账号 + 随机成员 Token + 项目 RBAC。当前没有自助注册、邮箱密码登录、找回密码、邮件邀请、支付计费或完整多租户数据迁移。管理员现有 Token、Cloudflare Access、开发机本地 Cookie 与部署密钥全部保持原有路径。

启用环境变量：`ARCU_TEAM_ACCESS_ENABLED=1`。默认 `0` 时所有成员与用户管理新接口禁用，已有管理员与部署密钥语义不变。不要在未经 HTTPS/Access 保护的公网 HTTP 环境中启用成员 Token。

## 权限矩阵

| 操作 | 全局管理员 | 成员 viewer | 成员 editor | 部署密钥 |
|---|---|---|---|---|
| 查看自己已授权的项目、版本、转换评估与历史 ZIP | 全部项目 | 是 | 是 | 仅原有指定查询 |
| 添加 HTML/ZIP 新版本、编辑版本说明、回滚 | 是 | 否 | 是 | 仅添加版本 |
| 创建新项目、重命名、归档/回收站、删除、站点发布 | 是 | 否 | 否 | 否 |
| 分享/管理分享与预览 Ticket、部署密钥、GitHub Workflow | 是 | 否 | 否 | 仅原有允许行为 |
| 创建/停用成员、轮换 Token、分配/撤销项目角色 | 是 | 否 | 否 | 否 |

项目角色只允许 `viewer` 与 `editor`。平台管理员始终独立于项目成员。成员的 `GET /api/projects` 列表只返回当前有权限、且未在回收站的项目；直接访问其他项目返回 404。其他未经授权操作返回 403。被停用的用户或被轮换的旧 Token 下一次请求立即变为 401。回收站项目对成员一律隐藏。

## 管理员 API

- `GET /api/me`：管理员返回 `{type:"admin",teamEnabled:true|false}`；成员返回 `{type:"member",user,memberships}`。部署密钥不支持此接口。
- `GET /api/users`：账号信息，不含 Token 或哈希。
- `POST /api/users`：`{name,email}`，返回 `id` 和仅此一次的 `uat_{16hex}.{43base64url}` 访问 Token。
- `PATCH /api/users/{userId}`：`{enabled:boolean}`。停用后旧 Token 不能再用。
- `POST /api/users/{userId}/rotate-token`：生成新 Token，旧 Token 立即失效。
- `GET /api/projects/{uuid}/members`：列出当前项目成员。
- `PUT /api/projects/{uuid}/members/{userId}`：`{role:"viewer"|"editor"}`。重复赋权幂等。
- `DELETE /api/projects/{uuid}/members/{userId}`：撤销访问，历史项目版本数据不删除。

以上团队管理端点只有全局管理员可访问。新接口错误保持 `{error,code}` 结构；所有 JSON 响应带 `Cache-Control: no-store`。

## 客户端操作

1. 在管理员工作台顶部点击「团队成员」，填写姓名和邮箱后创建账号，复制只展示一次的凭证（不自动发送邮件）。
2. 选中项目 →「项目管理」→「成员权限」，选择账号及 `只读` 或 `版本编辑`，点击保存。
3. 成员在 `/console` 的连接框粘贴 `uat_` Token：只显示已授权项目，隐藏团队管理、项目创建、分享、站点发布、部署密钥和删除操作。
4. 成员 Token 仅保存在当前浏览器标签的内存中，刷新需要重新连接。不允许成员 Token 作为网站预览票据或分享密钥使用。
5. 管理员可停用成员或轮换凭证；“停用账号”保留分配关系，“移除项目权限”只移除该项目授权。

## 存储与限制

- 账号登记保存在数据根目录 `.rc20-team.json`，原子写入及 0600 模式；只保存随机 Token 的 SHA-256 哈希，不保存 Token 明文。团队角色映射按 UUID 保存，未修改旧项目文件结构。
- 验权每次从磁盘重新读取当前用户状态与授权；单 Node 进程与原有 store 锁兼容。多实例/跨服务器共享数据库并发控制仍未实现，不可当作生产多租户方案。
- 不包含 Token 过期、登录速率限制、完整审计日志、SSO 多邮箱、MFA、独立账号注册/激活与找回。Token 泄露即代表成员身份，必须通过受信任的 HTTPS 和安全渠道交换。
- 服务端 `/p` 静态原型预览使用既有独立的安全模型；成员 Token **不授予**原型资源预览权。管理员需另行创建分享链接；成员 UI 隐藏不能直接打开的预览按钮。
- 后续 RC20B 计划正式身份提供商、多租户 owner 模型、邀请激活与成员预览票据（需单独评审威胁模型）。

## 回归测试与部署

测试覆盖：默认关闭、管理员兼容、成员 Token 哈希、跨项目隔离、只读拒绝写入、editor 限定版本操作、管理员专属能力禁止、撤销、禁用、轮换、回收站隐藏及旧部署密钥兼容。

该阶段仅 GitHub 开发与 CI，未操作 VPS、未自动部署到测试站或生产站。真实浏览器权限切换、账号管理弹窗和窄屏样式仍需部署到隔离测试环境后验收。
